🚀五分钟上手

RegexMate 免安装、免运行时：下载、解压、运行。以下四步走完，你已经把它接进了你的工具链。

  1. 下载二进制。到 Releases 页取对应平台的包（macOS Apple Silicon / Windows x64 / Linux x64），解压即得 regexmate CLI——包里还带原生桌面应用，不需要可略过。详见 平台覆盖。
  2. 第一条 validate。确认一个正则写没写对——错误单行输出，还带修复提示：
$ regexmate validate '^\d{4}-\d{2}-\d{2}$' Pattern: ^\d{4}-\d{2}-\d{2}$ ✓ Valid syntax
  1. 第一条 match。对文本（参数或 stdin）执行匹配，退出码语义化：
$ regexmate match '\d+' 'abc 123 def 456' Found 2 match(es): at 4-7: "123" at 12-15: "456"
  1. 接进你的 agent。在 MCP 客户端配置里加一段 JSON，八个工具即刻可用（完整说明见 MCP server）：
{ "mcpServers": { "regexmate": { "command": "regexmate", "args": ["mcp"] } } }

就这些。人类直接读彩色输出，agent 加一个 --json——其余章节都是可选的。

✅validate

检查正则语法（Racket pregexp 方言）。语法错误时输出单行错误和一行 Hint: 修复建议——这是 validate 独有的。

$ regexmate validate '[a-z' Pattern: [a-z ✗ Invalid syntax: missing closing square bracket in pattern Hint: a character class opens with [ and must close with ] — e.g. [a-z0-9]

退出码：0 语法有效 · 1 语法无效。加 --json 时错误对象同样携带 error 与 hint 键，agent 读 hint 再重试即可。

🔍match

对文本执行匹配。文本来自第二个参数，或用 - 从 stdin 读——管道里随手就能接。

# stdin in, human out $ echo 'ERROR 404' | regexmate match 'ERROR \d+' - Found 1 match(es): at 0-9: "ERROR 404"

--json 时输出结构化匹配：绝对区间 [start, end)、从 1 计数的捕获组。下面是 match '(\w+)@(\w+)' 'mail a@b and c@d' --json 的真实输出：

{"command":"match","count":2,"matches":[{"end":8,"groups":[{"end":6,"index":1,"name":false,"start":5,"value":"a"},{"end":8,"index":2,"name":false,"start":7,"value":"b"}],"start":5,"value":"a@b"},{"end":16,"groups":[{"end":14,"index":1,"name":false,"start":13,"value":"c"},{"end":16,"index":2,"name":false,"start":15,"value":"d"}],"start":13,"value":"c@d"}],"ok":true,"pattern":"(\\w+)@(\\w+)","schema":"regexmate/v1","text":"mail a@b and c@d"}

退出码：0 有匹配 · 3 语法有效但零匹配 · 1 正则无效。

💡explain

逐段解释一个正则——接手别人的正则时先跑一遍。默认英文，--lang zh 或环境变量 REGEXMATE_LANG=zh 切中文：

$ regexmate explain '(?:\d{2,4}|[a-z]+)(?=x)' Pattern: (?:\d{2,4}|[a-z]+)(?=x) Components: 1. [group] (?:\d{2,4}|[a-z]+) ← Non-capturing group (?:...): Digit (\d) × {2,4} | Character class: [a-z] × + 2. [lookaround] (?=x) ← Positive lookahead (?=...): Literal: x # --lang zh $ regexmate explain '\d+' --lang zh 正则表达式: \d+ 组成部分: 1. [quantifier] \d+ ← 数字 (\d) × +

🔁replace

替换并报告替换次数，替换文本里用 \1–\9 反向引用捕获组：

$ regexmate replace '(\d{4})-(\d{2})-(\d{2})' '\3/\2/\1' 'due 2026-10-14 ok' Replaced 1 occurrence(s). Result: due 14/10/2026 ok

退出码：0 有替换 · 3 语法有效但零替换 · 1 正则无效。

🗺️graph

把正则渲染成铁路图 SVG，用于规格文档和代码评审。默认写 stdout，-o FILE 落盘：

$ regexmate graph '\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])' -o date.svg SVG saved to: date.svg

--json 时 SVG 直接内嵌在 svg 键里；与 -o 同用时则报告 output（路径）和 bytes（大小）两个键。首页那张铁路图就是这个命令自己的输出。

🧪test

批量断言：正反用例各来一遍，逐条给出证据。用例是 JSON——text 必填，expect 取 match / no-match，可选 contains 检查匹配内容。用例文件参数或 stdin（-）皆可：

$ regexmate test '\d{4}-\d{2}-\d{2}' - <<'EOF' {"cases":[ {"text":"2026-09-28","expect":"match"}, {"text":"2026-13-01","expect":"match"}, {"text":"2026-9-28","expect":"match"} ]} EOF ✓ "2026-09-28" ✓ "2026-13-01" ✗ "2026-9-28" — expected a match but none was found Passed 2 of 3 case(s). # exit code 3

这就是 agent 的 write → test → refine 循环：退出码 0 全部通过 · 3 有用例失败（JSON 输出里逐条带 reason）· 1 正则本身无效。把通过的 JSON 输出留作改动证据。

🔬lint

确定性静态分析，抓 ReDoS 与死分支。不加 --strict 时只报告、退出码仍为 0：

$ regexmate lint '(a+)+$' 1 finding(s): [warning] nested-quantifier at 0: nested quantifiers over a group can backtrack catastrophically on non-matching input

--strict 把任何发现变成退出码 3——CI 门禁就靠它。规则一览：

规则 含义
nested-quantifier组上再叠无界量词——灾难性回溯（ReDoS）风险
quantified-assertion环视/锚点上的量词无效果或掩盖 bug
empty-branch空分支匹配一切——通常是 bug
duplicate-branch同一分支出现两次
shadowed-branch前面的分支永远命中，后面的分支不可达——调整顺序
portability该构造在 Racket 之外行为不同（原子组、内嵌旗标、POSIX/unicode 类、反向引用）
redundant-atomic单元素上的原子组不起作用

通用旗标：--json 结构化输出 · --lang en|zh 输出语言 · NO_COLOR 关闭 ANSI 高亮。用 regexmate --help 看全表。

🤖MCP server

regexmate mcp 启动 stdio 上的 JSON-RPC 2.0（换行分隔，协议版本 2024-11-05）MCP server。八个工具，各带输入 schema，可通过 tools/list 发现：

regexmate_validate · regexmate_match · regexmate_explain · regexmate_replace regexmate_graph · regexmate_test · regexmate_lint · regexmate_cookbook

Claude Code、Codex、Cursor 等任何支持 stdio MCP 的客户端都认这一段配置：

{ "mcpServers": { "regexmate": { "command": "regexmate", "args": ["mcp"] } } }

给 agent 的完整工作流（write → validate → test → lint → ship 循环与实例）见仓库里的 agents-guide.md。

📜versioned JSON contract

每个命令的 --json 输出都是单行信封，稳定键 schema（恒为 regexmate/v1）、command、ok 打头。规则：

  • 区间是绝对下标、[start, end) 半开；捕获组从 1 计数。
  • 键永不缺席：未命名组 "name":false；缺席的组 value/start/end 用 false 占位。
  • 错误是单行 error 字符串（无内嵌换行）；validate 的错误附 hint 修复建议。
  • graph --json 内嵌 svg；与 -o 同用时报告 output 与 bytes。
  • 契约本身机读：regexmate schema。破坏性变更必须先升 schema 版本，绝不悄悄改。

退出码四档，语义从不撒谎：

退出码含义
0成功——有匹配 / 语法有效 / 完成替换 / 用例全过
1正则表达式无效
2用法错误（错误选项、未知命令）
3语法有效但零匹配 / 零替换 / 用例失败 / lint --strict 有发现

正则方言是 Racket pregexp：支持环视、原子组、内嵌旗标、POSIX/Unicode 类、反向引用；不支持命名组 (?<name>…)、\A/\z、\x41——validate 会明确拒绝。

🖥️FAQ · 平台覆盖

每个 release 的 CLI 三平台都在发，但架构覆盖现状如下（其余架构请从源码构建：raco exe -o regexmate main.rkt，需 Racket 9.x）：

资产 平台 内容
regexmate-<版本>-macos-arm64.tar.gzmacOS 14+（仅 Apple Silicon）CLI + GUI
regexmate-<版本>-windows-x86_64.zipWindows 10+ x64CLI + GUI
regexmate-<版本>-windows-x86_64-standalone.exeWindows 10+ x64仅 CLI 的单文件
regexmate-<版本>-linux-x86_64.tar.gzLinux x64（GUI 需 GTK4）CLI + GUI

每个资产都有同名 .sha256 边车和汇总的 SHA256SUMS。macOS 包为 ad-hoc 签名：首次打开 GUI 需右键 → 打开。

🔌FAQ · MCP 配置

前提只有一个：regexmate 可执行文件在 PATH 里（不在的话把 command 写成绝对路径）。把这段放进客户端的 MCP 配置：

{ "mcpServers": { "regexmate": { "command": "regexmate", "args": ["mcp"] } } }

配置文件位置随客户端而异（Claude Code / Codex / Cursor 各有 mcpServers 段或等价界面）；保存后重启会话，用 tools/list 应能看到八个 regexmate_* 工具。

⬆️FAQ · 更新

应用内自更新（推荐）：先 regexmate update --check 探一眼，再 regexmate update。更新流程会验证 Ed25519 签名的更新清单（内嵌公钥，key id regexmate-2026-10）、核对下载的 SHA-256 与大小，然后把运行中的二进制原地换装——更新完 regexmate --version 确认；GUI 在同一包里，重启即可。

手动更新：从 Releases 下载新包、解压、覆盖旧文件即可——本来就免安装。raco pkg 安装的用 raco pkg update regexmate；源码安装 git pull 后重跑 raco exe。

🗑️FAQ · 卸载

RegexMate 免安装：没有安装器、不写用户配置目录，卸载就是删掉你解包出来的文件（CLI 二进制，连同不要的 GUI 应用）。更新产生的临时文件只出现在二进制旁边，随删除一起消失。若从 MCP 客户端接入过，顺手删掉配置里的 mcpServers 段。raco pkg 安装用 raco pkg remove regexmate。
